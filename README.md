# 旅行会話トレーナー

ポルトガル語（pt-PT）・スペイン語（es-ES）・イタリア語（it-IT）の旅行会話トレーナー。
旅行前に1言語をマスターしつつ、同じ意味の他言語（英語を含む）を同画面で比較できる。
フレームワークなし、単一ページ、バニラJS。`package.json` は持たない。

多言語化の設計は [docs/SPEC-multilingual.md](docs/SPEC-multilingual.md) にある。
以下の記述はポルトガル語専用だった時点のもので、実装フェーズごとに更新する。

フレーズ150文。出発日を入れると、そこから逆算して45日程度の学習計画を自動で組む。

出発日はソースコードに持たない。初回起動時に入力し、その端末のlocalStorageにだけ保存する。
公開リポジトリに旅行時期を残さないための設計。

## 起動

```bash
cd ~/dev/ai_sandbox/polyglot-trainer && python3 tools/serve.py
```

ブラウザで http://localhost:8765 を開く。`file://` では ES モジュールと `fetch` が動かないため
必ずHTTPで開く。止めるときは Ctrl+C。

`python3 -m http.server` でも配信はできるが、ブラウザが js をキャッシュするため、
コードを更新したのに古いモジュールが読み込まれて壊れることがある。`tools/serve.py` は
`Cache-Control: no-store` を付けてこれを防ぐので、開発中はこちらを使う。

基準日を差し替えて動作確認する場合はクエリを付ける。

```
http://localhost:8765/?today=2030-05-10
```

### 画面が壊れたとき

設定画面の「ビルド」欄に版番号（`js/app.js` の `APP_VERSION`）が出る。
更新したはずの番号と違えばキャッシュが残っているので、スーパーリロードする。

- macOS の Chrome / Safari: Cmd+Shift+R
- それでも直らない場合は開発者ツールを開いた状態でリロード

`Cannot read properties of null (reading 'addEventListener')` は、
古い app.js が現在の index.html に無い要素を参照したときに出る典型的な症状。

## テスト

```bash
cd ~/dev/ai_sandbox/portuguese-trainer && node tools/test-srs.mjs
```

SRSの2段スケジューラを検証する。箱ごとの間隔、同日再挑戦の最悪採点、スイープ10日での

テストは架空の旅程（出発 2030-05-20）で回す。実在の旅程はリポジトリに含めない。

## 手動での動作確認

### 0. 出発日の入力

初回は出発日の入力画面が出る。日付を入れて「はじめる」を押すとホームに進む。
入力値は `localStorage` の `pt.trip` にだけ入り、ソースにもサーバーにも残らない。
設定画面の「出発日」からいつでも変更できる。明日以降の日付でないと弾かれる。

以降の手順の `?today=` は、入力した出発日を基準に読み替える。

初日は新規カードだけで復習は出ない。復習は2日目から出る。両方を確認するには
`?today=` を1日ずつ進める。

### 1. 初日（新規のみ）

進捗が残っていると結果が変わるため、まず設定画面の「進捗をすべて消す」で初期化する。

```
http://localhost:8765/?today=<学習初日>
```

ホームの表示: 出発まで 45日 / ストリーク 0 / 定着 0 / 150 / ボタン下に「新規 5」

「今日の10分をはじめる」を押すと新規カードが5枚出る。順序は phrases.json の先頭5件。

| 表示 | ポルトガル語 | 日本語 |
|---|---|---|
| 新規 1/5 | Bom dia. | おはようございます |
| 新規 2/5 | Boa tarde. | こんにちは（昼から日没まで） |
| 新規 3/5 | Boa noite. | こんばんは / おやすみなさい |
| 新規 4/5 | Olá. | やあ（カジュアル） |
| 新規 5/5 | Obrigado. | ありがとう |

新規カードは最初から全部見える。カードを開いた時点で音声が自動再生される。
下に進むボタンは「次へ」だけ。採点は出ない（まだ覚えていないので採点する意味がない）。

カード上の要素は上から、シーン名（あいさつ）、日本語、ポルトガル語、カナ、
「もう一度聞く」「ゆっくり」、イタリア語、メモ。

5枚終えると完了画面。「完了 / 1 日連続 / 新規 5枚」と出る。

ホームに戻るとボタンが「もう一度やる（5枚）」に変わり、その下に「今日の分は完了。何回でも
復習できる」と出る。

新規は1日5枚が上限で、同じ日に何度開いても増えない。途中で中断した場合だけ残り枚数が出る。
これは仕様。既存の朝の習慣を圧迫しないためにセッションを10分以内に抑える設計で、
先に進めても翌日以降の復習量が増えるだけで定着はしない。

### 1b. もう一度やる（同日の再挑戦）

ホームのボタンは常に1つで、状態によって行き先が変わる。押せないボタンは置かない。

| 状態 | ボタン |
|---|---|
| その日の必須分が残っている | 今日の10分をはじめる |
| 必須分は終わった | もう一度やる（N枚） |
| 対象カードが1枚もない | 今日の出題はなし（押せない） |
| 出発日以降 | 旅行モード（Phase 3で実装） |

「完了」を押して操作を打ち切る作りにはしていない。最後にするつもりがなくても結果的に
最後の1回になることがあり、区切りを宣言させる意味がないため。ストリークは1日1回だけ
加算されるので、何回やっても増えないし減らない。

「もう一度やる」は何回でも押せる。その日にさわったカード（採点済み + 当日投入分）だけを、
間違えたものから順に出す。新規は増えない。ラベルは「再挑戦 1/5」になる。

採点は**その日の最悪の採点が勝つ**。朝に「だめ」を付けたカードを夜に「できた」にしても
箱1のまま翌日に出る。1回でも間違えた事実が翌日以降の予定に反映される。

- 「だめ」→ 後で正解しても箱1のまま、翌日に出る
- 「できた」だけを何回繰り返しても箱は1つしか進まない
- 同じ日に何度間違えても lapses は1しか増えない（「間違えた日数」を数える）
- 翌日は前日の記録を引きずらず、新しく判定される

完了画面に「間違えた N枚は明日また出ます」と出る。

投入日は昇格しない。新規カードを当日の再挑戦で正解しても箱1のままで、翌日必ず復習に出る。
当日の正解は記憶の新しさによるもので、定着の証拠にならないため。

### 2. 2日目（ここで初めて復習が出る）

```
http://localhost:8765/?today=<学習2日目>
```

ホームの表示: 出発まで 44日 / ストリーク 1 / 「復習 5 / 新規 5」

セッションは復習5枚が先、新規5枚が後。分母は合計の10。

- 復習 1/10 〜 復習 5/10 が Bom dia 〜 Obrigado（前日の5枚）
- 新規 6/10 〜 新規 10/10 が Muito obrigado / De nada / Por favor / Faz favor / Com licença

復習カードは日本語しか出ない。ポルトガル語を声に出してから「答えを見る」を押す。
押すと答えと音声が出て、採点の3択が現れる。

### 3. 採点3択の意味

学習2日目に箱1のカードを採点した場合の次回出題日。

| ボタン | 箱 | 次回 | その他 |
|---|---|---|---|
| できた | 1 → 2 | 2日後 | |
| あいまい | 1 のまま | 1日後 | |
| だめ | 1 のまま | 1日後 | lapses+1。そのセッションの末尾に再出題される |

「だめ」を押すと分母が1増える。1枚目で「だめ」を押すと次のカードが「復習 2/11」になり、
最後に同じカードが「復習 11/11」として再び出る。これは意図した動作。

同じ日に「もう一度やる」で採点し直した場合は、当日最初の採点時点の箱を基準に再計算する。
何度繰り返しても状態が累積しない。詳細は上の 1b を参照。

### 4. 定着カウンタ

ホームの「定着」は箱4以上（間隔8日に到達）のカード数。1〜2日では増えない。
できたを3回続けて初めて1枚が箱4に入る。0 / 150 のままでも異常ではない。

### 5. 音声

設定を開き「音声」の行を見る。期待する表示は次の形。

```
ヨーロッパポルトガル語（pt-PT）の音声を使用中: <音声名> / MP3 0件
```

「pt-PT音声なし。ブラジル音声で代用中」と出た場合はPhase 3のMP3生成を前倒しする。
ブラジル発音で覚えると現地で通じにくくなるため、この確認は重要。

### 6. 進捗の永続化

セッション完了後にページを再読み込みし、ストリークと定着が残っていることを確認する。
設定の「JSONを書き出す」でファイルを保存し、「進捗をすべて消す」の後に「JSONを読み込む」で
戻せることも確認する。

### 7. スイープ期と旅行モード

上記の1日目と2日目を終えて10枚投入した状態で開く。

```
http://localhost:8765/?today=<出発日の10日前>
```

ホームに「最終スイープ・復習 1」と出る。投入済み10枚を10日へ1枚ずつ割り当てるため初日は1枚。
「だめ」を2回以上付けたカードがあると2枚になる。新規は出ない。
本番どおり150枚を投入し終えていれば15枚前後になる。

```
http://localhost:8765/?today=<出発日>
```

出発まで 0日、「旅行中」と表示され、ボタンが押せなくなる。旅行モードの画面はPhase 3で実装する。

進捗ゼロのままスイープ期の日付を開くと対象カードが無く「今日の出題はなし」になる。
先に1日目と2日目を済ませておく。

## SRSの設計

通常のSRSは間隔を無限に延ばすため、出発時点で「最後に見たのが3週間前」のカードが生じる。
これを構造的に禁止するため、日付でスケジューラを切り替える。第1段は普通の箱方式で伸ばし、
出発直前の第2段で全カードを必ず1周させる。

### 第1段 学習期（開始日〜出発の11日前）

箱1〜5。間隔は 1 / 2 / 4 / 8 / 14 日で、残日数によらず一定。
新規は1日5枚。復習は1セッション30枚で打ち切り、超過は翌日へまわす。

当初は残日数に応じて最大間隔を圧縮していたが、150枚では逆効果だったため外した。
出発直前に間隔を3日まで詰めると需要が1日50枚に達し、上限30枚では吸収できず未消化が
積み上がる。しかも枠を食うのは箱4〜5の定着済みカードで、弱いカードが押し出されていた。
圧縮を外すと未消化は48枚→8枚、定着は99→108（8シード平均）に改善した。

「出発時点で最後に見たのが3週間前」を防ぐ役割は第2段のスイープが担う。第1段で
消化しきれなかったカードも、スイープで必ず1回は出題される。

繰り越しはゼロにはならない。150枚を1日30枚で回す以上、詰まる日は出る。
12シードの計測では期間中の最大29枚、学習期最終日に最大19枚が残った。
これは失敗ではなく、スイープが回収する前提の設計。

### 第2段 最終スイープ（出発の10日前〜出発前日）

箱のスケジュールを止め、全カードを10日間へ均等割り当てする。

1回目の割り当ては**カリキュラム順のインデックスだけ**で決める（`i % 10`）。これは不変値なので、
スイープ中に `lapses` が増えて計画が再計算されても割り当てが動かず、全カードが必ず1回は
出題されることが保証される。弱点カードの2回目・3回目は基準日から半周・1/3周ずらした日に足す。

各日の出題順は1回目の割り当てを先頭に置く。上限25枚で切り捨てられるのは常に追加分だけになり、
網羅性が崩れない。

### 旅行モード（出発日以降）

`modeFor()` が `trip` を返す。学習を止め実戦フレーズブックに切り替える（Phase 3で実装）。

## フレーズの追加

`data/phrases.json` の `phrases` 配列に足す。該当weekの末尾に置くと投入順が自然になる。

```json
{
  "id": "rest-order-99",
  "scene": "restaurante",
  "week": 2,
  "jp": "これをください",
  "pt": "Queria isto, por favor.",
  "kana": "キリア イシュトゥ、プル ファヴォール",
  "it": "Vorrei questo, per favore",
  "note": "Queria は Eu quero より丁寧",
  "tags": ["core", "must"]
}
```

`scene` は greet / basic / numero / pedir / restaurante / cafe / transporte / hotel /
compras / problema。追加する場合は `js/app.js` の `SCENE_LABELS` にも日本語名を足す。
`it` はイタリア語ブリッジ（イタリア語検定4級の知識を転用するための対応付け）。
`kana` はpt-PTの実際の発音に寄せる。語末sは「シュ」、無強勢のeは脱落。

## 音声

`audio/{id}.mp3` があればそれを再生し、なければブラウザ内蔵TTSで `lang='pt-PT'` を使う。
MP3の有無は `data/audio-manifest.json`（ID配列）で判定する。このファイルが無い間はTTSのみで動く。

ブラジル音声(pt-BR)で代用すると発音を誤学習するため、pt-PT音声が無い端末では警告を出す。
端末の音声一覧は設定画面で確認できる。

Phase 3で `tools/gen_audio.py` によりGoogle Cloud TTSのpt-PT WaveNet音声から一括生成する。

## 進捗データ

localStorage の `pt.cards`（カード）、`pt.meta`（ストリーク等）、`pt.trip`（出発日）。
iOSのPWAは長期未使用でストレージが破棄されうるため、設定画面からJSONを書き出せる。
機種変更や事故のときは同じ画面から読み戻す。書き出したJSONには出発日が入るので、
リポジトリにコミットしないよう注意する。

カード1枚は次の形。

```json
{ "id": "greet-01", "box": 2, "lapses": 0, "due": "2030-04-13",
  "firstSeen": "2030-04-10", "lastSeen": "2030-04-11",
  "gradedOn": "2030-04-11", "dayWorst": "good", "preBox": 1 }
```

| 項目 | 意味 |
|---|---|
| `box` | 1〜5。間隔を決める |
| `lapses` | 間違えた日数。同じ日に何度間違えても1 |
| `due` | 次に出る日 |
| `firstSeen` | 投入日。固定。1日の新規上限の判定と、投入日の昇格禁止に使う |
| `lastSeen` | 最後に採点した日 |
| `gradedOn` | 採点した日。同日の再挑戦かどうかの判定に使う |
| `dayWorst` | その日に付いた最悪の採点 |
| `preBox` | その日最初の採点時点の箱。再挑戦の再計算の基準 |

### 検証

```bash
node tools/check-phrases.mjs && node tools/test-srs.mjs && node tools/test-store.mjs
```

`tools/check-phrases.mjs` は `data/phrases.json` を40項目で検証する。`--self-test` を
付けると検証ツール自身のテストが走る。

**スイープの網羅保証には上限がある。** `SWEEP_DAYS × SWEEP_CAP = 10 × 25 = 250枚`を
超えると、1回目の割り当てまで切り捨てられて出題されないカードが無警告で発生する。
検証ツールが200枚超を警告、250枚超をエラーにする。

**スイープ期間中は `phrases` 配列への末尾追記だけにする。** 途中挿入すると
`i % n` の割り当てが全カードでずれ、約15枚が出題されなくなる。実装側でも
スイープ突入時に並びを `trip.sweepOrder` へ凍結して防いでいるが、編集規約としても守る。

**フレーズのidは恒久で、再利用しない。** 消したidを別の意味で使い回すと、
古い箱や `suspended` を新しいフレーズが継承し、一度も見ていないフレーズが
永久に除外される。設定画面に「孤立した進捗」として可視化してある。

### フレーズの追加

`data/phrases.json` の `phrases` 配列に足す。`langs` に4言語すべてを入れ、
`scenes` と `tags` に無いキーは使わない（検証ツールがエラーにする）。

```json
{
  "id": "rest-order-99",
  "scene": "restaurante",
  "week": 2,
  "jp": "これをください",
  "tags": ["core", "must"],
  "langs": {
    "pt": { "text": "Queria isto, por favor.", "kana": "キリア イシュトゥ、プル ファヴォール", "note": "Queria は Eu quero より丁寧" },
    "es": { "text": "Quería esto, por favor.", "kana": "ケリア エスト、ポル ファボール", "note": "ptのQueriaと同形" },
    "it": { "text": "Vorrei questo, per favore.", "kana": "ヴォッレイ クエスト、ペル ファヴォーレ", "note": "volereの条件法" },
    "en": { "text": "I'd like this, please." }
  }
}
```

### 進捗データ

localStorage の `poly.progress`（言語別のカード）、`poly.trips`（言語別の出発日）、
`poly.meta`（ストリーク等。言語横断で1つ）、`poly.settings`（主言語）。

GitHub Pages では `ユーザー名.github.io` がリポジトリをまたいで同一オリジンになるため、
このキー改名が旧アプリとの衝突を防いでいる。

書き出しJSONには全言語の出発日が入るので、リポジトリにコミットしない。
